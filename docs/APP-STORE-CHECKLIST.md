# 上架檢查清單：App Store 與 Google Play

> 這份清單分成「兩個平台都要」與各平台專屬，並標記 **✅ 已完成**（專案裡已經做好）
> 或 **⬜ 你要做**。圖片素材需求放在最後。

---

## 1. 兩個平台都要準備

| 項目 | 狀態 | 說明 / 位置 |
| --- | --- | --- |
| 可公開存取的隱私政策網址 | ⬜ | 用 `web/privacy.html`，部署到 GitHub Pages 後就是一個網址。內容要與 App 實際行為一致 |
| App 內可刪除帳號 | ✅ | 「我的 → 帳號與資料 → 刪除我的帳號與資料」，對應 `delete_my_account()` |
| 帳號刪除的網頁入口（選配） | ⬜ | Google 對「有帳號的 App」額外要求提供網頁版刪除說明，可在 `privacy.html` 加一節說明即可 |
| 客服聯絡方式 | ⬜ | `web/app.js` 的 `CONFIG.supportEmail` 目前是 `support@example.com`，**一定要改成你真的會收信的信箱** |
| 開發者帳號 | ⬜ | Apple：每年 99 美元（公司帳號需 D-U-N-S 編號）。Google：一次性 25 美元，近幾年要求先做身分驗證，可能要等幾天 |
| App 圖示 | ✅ | 已產生並安裝，1024×1024 |
| 啟動畫面 | ✅ | 已產生並安裝，含深色版 |
| 版本號自動遞增 | ✅ | CI 用 GitHub 執行序號，不會重複 |
| App 名稱 | ✅ | Orbit（要改就改 `strings.xml` 與 `Info.plist`） |
| 出口合規（加密）申報 | ⬜ | 只用標準 HTTPS，屬豁免範圍，但上傳時仍要回答「是否使用加密」 |

## 2. App Store（iOS）專屬

| 項目 | 狀態 | 說明 |
| --- | --- | --- |
| Apple Developer Program | ⬜ | 個人帳號最快當天可通過 |
| App ID / Bundle ID | ⬜ | 必須與 `capacitor.config.json` 的 `appId` 一致 |
| 發佈憑證 + Provisioning Profile | ⬜ | 見 `docs/BUILD.md` 第 2.4 節 |
| App Store Connect App 記錄 | ⬜ | 建立時要選對 Bundle ID 與主要語言 |
| 年齡分級問卷 | ⬜ | 習慣工具通常為 4+ |
| 資料收集宣告（App Privacy） | ⬜ | 依實情勾選：**Email 地址（與身分連結、用於 App 功能）**、**使用者內容（習慣與打卡紀錄）**。不要勾選追蹤，因為沒有廣告 SDK |
| 隱私政策網址 | ⬜ | 填入 App Store Connect |
| 支援網址 | ⬜ | 可先用 GitHub Pages 上的頁面 |
| 審核備註（App Review Notes） | ⬜ | **重要**：提供一組測試帳號與密碼，讓審核員能登入看到同步功能；只寫「請自行註冊」常被退件 |
| 截圖 | ⬜ | 6.7 吋與 6.5 吋 iPhone 必填，iPad 若支援也要（本專案已鎖定直向，只需直向截圖） |
| App 預覽影片 | ⬜ | 選配 |
| 上傳方式 | ⬜ | Transporter 或 Xcode Organizer，把 CI 產出的 `.ipa` 送上傳 |
| TestFlight 測試 | ⬜ | 建議先內部測試，確認登入與同步正常再送審 |

**常見退件原因（提前避開）**
- 沒有提供測試帳號 → 審核員進不去。
- 隱私政策網址打不開或是空白頁。
- 帳號刪除功能找不到（Apple 明確要求 App 內可刪）。
- 審核時雲端服務掛掉或 Supabase 免費專案被暫停。

## 3. Google Play（Android）專屬

| 項目 | 狀態 | 說明 |
| --- | --- | --- |
| Google Play Console 帳號 | ⬜ | 25 美元一次性，需身分驗證 |
| 上傳格式 | ⬜ | 用 CI 產出的 `.aab`（App Bundle），不是 APK |
| 應用程式簽章 | ⬜ | 建議啟用 Play App Signing，由 Google 保管正式金鑰；CI 用的金鑰則作為上傳金鑰 |
| 商店資訊 | ⬜ | 名稱、簡短說明（80 字元）、完整說明（4000 字元） |
| 圖示 512×512 | ✅ | `store/play-store-icon-512.png` |
| 精選圖片 1024×500 | ⬜ | 需要自製 |
| 手機螢幕截圖 | ⬜ | 至少 2 張，建議 4～8 張 |
| 資料安全表單（Data safety） | ⬜ | 蒐集 Email 與使用者內容；資料加密傳輸；提供刪除機制。**與隱私政策必須一致** |
| 內容分級問卷 | ⬜ | 依實情填答 |
| 目標對象與「家庭政策」 | ⬜ | 選 13 歲以上可避開家庭政策額外要求 |
| 廣告宣告 | ⬜ | 無廣告 |
| 封閉測試（Closed testing） | ⬜ | **新個人開發者帳號通常需要先跑一定人數的封閉測試才能申請正式發布**，請預留時間 |
| 隱私政策網址 | ⬜ | 填在商店資訊 |

| App 預覽影片（選配） | 1080×1920 | ⬜ |

**截圖建議內容**（依 App 現有畫面）

2. 打卡瞬間（勾選後狀態）
3. 統計頁：近七天長條圖
4. 習慣編輯：選擇重複的日子
5. 深色模式對照

## 5. 送審前的自我測試（真機）

- [ ] 全新安裝 → 開場就是今日頁，不閃退
- [ ] 訪客模式新增習慣 → 完全關閉 App 再開 → 資料還在
- [ ] 用任意 Gmail／公司信箱註冊 → 能登入（或收到驗證信）
- [ ] 在手機登入後，用電腦瀏覽器登入同一帳號 → 看到相同習慣
- [ ] 飛航模式打卡 → 恢復網路後自動同步，不重複、不遺失
- [ ] 刪除一個習慣 → 相關打卡紀錄一起消失，雲端也消失
- [ ] 刪除帳號 → 之後無法再用同一組帳密登入
- [ ] 深色模式切換正常，切到系統深色時自動跟著變
- [ ] 鍵盤彈出時輸入框沒有被遮住
- [ ] Android 實體返回鍵：關閉彈窗 → 回到今日頁 → 才離開 App
- [ ] 密碼重設信件能收到，且點連結後能設定新密碼

---

## 6. 建議的上線順序

1. 先把 `web/` 部署到 GitHub Pages，確認隱私政策網址能開。
2. 依 `docs/SUPABASE-SETUP.md` 設好 SMTP 與 Redirect URL，用真信箱測試註冊。
3. 跑 GitHub Actions 取得 APK，裝在自己的 Android 手機上實際用一週。
4. 修完問題後，設定簽章 Secrets，產出正式 AAB 與 IPA。
5. 先送 Google Play 封閉測試（等待期較長），同時送 App Store 審核。
6. 兩邊都通過後再公開，並保留前一版可供回退。
